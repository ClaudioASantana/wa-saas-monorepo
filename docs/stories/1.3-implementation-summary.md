# Story 1.3: Implementação do Sistema de Recuperação de Senha

**Data de Implementação:** 2026-07-09  
**Status:** ✅ Implementado  
**Epic:** [EPIC-1](../epics/epic-1-auth.md)

## 📋 Resumo

Implementação completa do fluxo de recuperação de senha usando JWT custom (sem Supabase Auth), com tokens temporários armazenados em PostgreSQL e envio de links por email.

## 🏗️ Arquitetura Implementada

### Infraestrutura (Docker)

#### Mailpit - Servidor de Email Local

**Arquivo:** [`docker-compose.yml`](../../docker-compose.yml)

Adicionado serviço Mailpit para desenvolvimento:

```yaml
mailpit:
  image: axllent/mailpit:latest
  container_name: wa-mailpit
  restart: always
  ports:
    - '1025:1025' # SMTP server
    - '8025:8025' # Web UI
  environment:
    MP_SMTP_AUTH_ACCEPT_ANY: 1
    MP_SMTP_AUTH_ALLOW_INSECURE: 1
    MP_MAX_MESSAGES: 5000
    MP_DATABASE: /data/mailpit.db
  volumes:
    - wa_mailpit_data:/data
```

**Características:**

- Interface web em `http://localhost:8025` para visualizar emails
- SMTP em `localhost:1025` (sem autenticação em dev)
- Armazena até 5000 mensagens
- Ideal para desenvolvimento e testes

#### 1. Migration de Banco de Dados

**Arquivo:** [`apps/api/src/db/migrations/006_password_reset_tokens.sql`](../../apps/api/src/db/migrations/006_password_reset_tokens.sql)

Tabela criada:

```sql
CREATE TABLE password_reset_tokens (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  agent_id UUID NOT NULL REFERENCES agents(id) ON DELETE CASCADE,
  token VARCHAR(255) NOT NULL UNIQUE,
  expires_at TIMESTAMP NOT NULL,
  used_at TIMESTAMP DEFAULT NULL,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

**Características:**

- Token único com hash SHA256
- TTL de 1 hora
- Marcação de uso (used_at)
- Índices para performance

#### 2. Helper de Tokens

**Arquivo:** [`apps/api/src/utils/password-reset-token.ts`](../../apps/api/src/utils/password-reset-token.ts)

**Funções:**

- `generatePasswordResetToken()` - Gera token seguro de 64 caracteres hex
- `hashToken(token)` - Cria hash SHA256 para armazenamento
- `getTokenExpiration()` - Calcula expiração (1 hora)
- `isTokenExpired(date)` - Verifica se token expirou

**Segurança:**

- Usa `crypto.randomBytes(32)` para geração
- Armazena apenas hash no banco
- Usa helpers UTC do projeto (`utcNow`, `addHours`, `isExpired`)

#### 3. Endpoints de API

**Arquivo:** [`apps/api/src/routes/auth.ts`](../../apps/api/src/routes/auth.ts)

##### POST `/auth/forgot-password`

```typescript
Body: { email: string }
Rate Limit: 3 req/15min
```

**Fluxo:**

1. Valida email
2. Busca agente ativo no banco
3. Gera token seguro
4. Armazena hash do token com expiração
5. **Envia email com link de recuperação** (via nodemailer)
6. Retorna sempre sucesso (previne email enumeration)

**Logs de Auditoria:**

- `password_reset_requested` - Quando token é gerado
- `email_sent` - Quando email é enviado com sucesso
- `email_send_failed` - Se envio de email falhar (não bloqueia o fluxo)

##### POST `/auth/reset-password`

```typescript
Body: { token: string, password: string }
Rate Limit: 5 req/15min
```

**Fluxo:**

1. Valida token e senha
2. Aplica validação de força de senha (Story 1.6)
3. Busca token no banco (por hash)
4. Valida: não usado, não expirado
5. Atualiza senha com bcrypt (transação)
6. Marca token como usado
7. Log de auditoria

**Validações:**

- Token obrigatório e válido
- Senha: 8+ chars, maiúsc, minúsc, número, especial
- Token não pode ser reutilizado
- Expira em 1 hora

## 🧪 Como Testar

### 1. Solicitar Recuperação de Senha

```bash
curl -X POST http://localhost:4000/auth/forgot-password \
  -H "Content-Type: application/json" \
  -d '{"email":"usuario@example.com"}'
```

**Resposta esperada:**

```json
{
  "message": "Se o email existir, você receberá instruções em breve"
}
```

**Verificar logs da API:**
Buscar o `resetLink` temporário no log (linha com `password_reset_requested`)

### 2. Redefinir Senha

```bash
curl -X POST http://localhost:4000/auth/reset-password \
  -H "Content-Type: application/json" \
  -d '{
    "token":"<token-do-log>",
    "password":"NovaSenha123!@"
  }'
```

**Resposta esperada:**

```json
{
  "message": "Senha redefinida com sucesso"
}
```

### 3. Testar no Frontend

1. Acessar: `http://localhost:3000/esqueci-senha`
2. Digitar email cadastrado
3. Copiar link do log da API
4. Acessar link: `http://localhost:3000/redefinir-senha?token=xxx`
5. Definir nova senha
6. Fazer login com nova senha

### 4. Testar Validações

**Senha fraca:**

```bash
curl -X POST http://localhost:4000/auth/reset-password \
  -H "Content-Type: application/json" \
  -d '{"token":"xxx","password":"123"}'
```

**Token expirado:**
Aguardar 1 hora e tentar usar o mesmo token

**Token já usado:**
Tentar usar o mesmo token duas vezes
