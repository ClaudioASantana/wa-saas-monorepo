## Descrição

Implementar o fluxo completo de "Esqueci minha senha" usando autenticação JWT custom (sem Supabase Auth), permitindo que usuários recuperem acesso às suas contas através de tokens temporários enviados por email.

---

## Contexto

Esta story foi atualizada para refletir a decisão arquitetural de usar **JWT custom** ao invés de Supabase Auth. A implementação usa:

- PostgreSQL direto (tabela `password_reset_tokens`)
- Tokens seguros gerados com `crypto.randomBytes`
- Hash SHA256 para armazenamento
- TTL de 1 hora
- Rate limiting para segurança

## Implementação

### Arquitetura

**Fluxo Completo:**

1. Usuário acessa `/esqueci-senha` e informa email
2. Backend gera token seguro e armazena hash no banco
3. Backend retorna sucesso (mesmo se email não existir)
4. Backend loga link temporário (DEV ONLY)
5. Usuário acessa link: `/redefinir-senha?token=xxx`
6. Frontend valida token e força da senha
7. Backend valida token (não usado, não expirado)
8. Backend atualiza senha e marca token como usado
9. Usuário é redirecionado para login

### Segurança

**Backend:**

- Rate limit: 3 req/15min (forgot), 5 req/15min (reset)
- Token gerado com `crypto.randomBytes(32)` (64 chars hex)
- Hash SHA256 armazenado no banco
- TTL de 1 hora
- Token de uso único
- Validação de senha: 8+ chars, maiúsc, minúsc, número, especial
- Proteção contra email enumeration
- Transações garantem atomicidade

**Frontend:**

- Validação client-side em tempo real
- Mensagens genéricas de erro
- Tratamento de rate limit
- Loading states

## Notas Técnicas

### Diferenças vs Planejamento Original

**Planejamento:**

- Usar Supabase Auth para recuperação de senha
- Templates de email do Supabase

**Implementado:**

- Sistema custom com PostgreSQL direto
- Tokens próprios com crypto seguro
- Preparado para integração com qualquer provedor de email

**Motivo:** Decisão arquitetural de remover dependência do Supabase Auth e manter controle total sobre autenticação (confirmado em Story 1.6 e revisão de 2026-07-07).
