## Descrição

Implementar melhorias críticas de segurança no sistema de autenticação JWT custom, removendo riscos bloqueantes para produção: fallback inseguro do `JWT_SECRET`, ausência de rate limiting, validação fraca de senha e ausência de proteção adicional para endpoints sensíveis.

Esta story nasce da revisão técnica registrada em [`docs/analise/revisao-sistema-autenticacao-2026-07-07.md`](../analise/revisao-sistema-autenticacao-2026-07-07.md).

---

## Contexto

A decisão arquitetural confirmada é **remover/evitar Supabase Auth** e manter autenticação custom com:

- Fastify
- PostgreSQL direto
- bcrypt
- JWT
- cookies no frontend Nuxt

Com isso, a responsabilidade por hardening de autenticação passa a ser do próprio projeto. Esta story cobre as correções mínimas para reduzir riscos de força bruta, senhas fracas e configuração insegura.

## Notas Técnicas

### Validação mínima de senha

```ts
type PasswordValidationResult = {
  valid: boolean
  error?: string
}

export function validatePassword(password: string): PasswordValidationResult {
  if (password.length < 8) {
    return { valid: false, error: 'Senha deve ter pelo menos 8 caracteres' }
  }

  if (!/[A-Z]/.test(password)) {
    return { valid: false, error: 'Senha deve conter pelo menos uma letra maiúscula' }
  }

  if (!/[a-z]/.test(password)) {
    return { valid: false, error: 'Senha deve conter pelo menos uma letra minúscula' }
  }

  if (!/[0-9]/.test(password)) {
    return { valid: false, error: 'Senha deve conter pelo menos um número' }
  }

  if (!/[^A-Za-z0-9]/.test(password)) {
    return { valid: false, error: 'Senha deve conter pelo menos um caractere especial' }
  }

  return { valid: true }
}
```

### JWT secret obrigatório

```ts
const JWT_SECRET = process.env.JWT_SECRET

if (!JWT_SECRET) {
  throw new Error('JWT_SECRET environment variable is required')
}
```

## Riscos

| Risco                                                | Impacto | Mitigação                                        |
| ---------------------------------------------------- | ------- | ------------------------------------------------ |
| Rate limit muito agressivo afetar usuários legítimos | Médio   | Ajustar limites após observabilidade             |
| Validação de senha quebrar cadastro existente        | Médio   | Aplicar apenas a novos cadastros/trocas de senha |
| Logs exporem dados sensíveis                         | Alto    | Nunca logar senha, token completo ou hash        |
| Configuração ausente em ambiente local               | Baixo   | Atualizar `.env.example` e docs                  |
