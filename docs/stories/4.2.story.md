# Story 4.2: Billing & Assinatura (Stripe)

**Status:** Done

Como dono de workspace, quero gerenciar minha assinatura e pagamento, para que eu possa fazer upgrade/downgrade do plano e manter o acesso ao sistema.

## Acceptance Criteria

1. **Rota `/assinatura`**: Exibe plano atual, data de renovação, número de agentes e botão "Gerenciar Assinatura".
2. **Checkout**: Botão "Fazer Upgrade" redireciona para Stripe Checkout com o plano selecionado.
3. **Portal do Cliente**: Botão "Gerenciar" abre o Stripe Customer Portal para alterar cartão, cancelar ou trocar plano.
4. **Webhook Stripe**: Eventos `customer.subscription.updated` e `customer.subscription.deleted` atualizam status do workspace no banco.
5. **Bloqueio**: Workspaces com assinatura expirada/cancelada exibem banner de aviso e bloqueiam criação de novos agentes.
6. **Planos**: Mínimo 2 planos — Starter (até 3 agentes) e Pro (agentes ilimitados).

## Technical Details

- **Schema DB**: Adicionar colunas `stripe_customer_id`, `stripe_subscription_id`, `plan`, `subscription_status` na tabela `workspaces`.
- **Endpoints**:
  - `POST /api/billing/checkout` — cria Stripe Checkout Session
  - `POST /api/billing/portal` — cria Stripe Customer Portal Session
  - `POST /api/billing/webhook` — processa webhooks do Stripe (verificar assinatura com `stripe.webhooks.constructEvent`)
- **Env vars**: `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET`, `STRIPE_PRICE_STARTER`, `STRIPE_PRICE_PRO`.
- **Página**: `pages/assinatura.vue` com layout padrão.

## Implementation Notes (2026-05-11)

### Resumo das Atividades
Concluímos a integração completa do Stripe no `wa-saas-monorepo` para gerenciar assinaturas SaaS, incluindo fluxo de checkout, portal do cliente e webhooks de sincronização.

### 1. Funcionalidades Adicionadas
*   **Banco de Dados**: Migração `20260511213400_add_billing_to_workspaces.sql` adicionou colunas de cobrança à tabela `workspaces`. Tipos TypeScript em `database.types.ts` foram atualizados.
*   **Endpoints de API (`apps/web/server/api/billing/`)**:
    *   `checkout.post.ts`: Cria sessões de assinatura Stripe e atrela o `customer_id` ao workspace.
    *   `portal.post.ts`: Acesso seguro ao portal de gestão de faturas e cartões do Stripe.
    *   `webhook.post.ts`: Processa eventos (`subscription.updated`, `subscription.deleted`, `checkout.session.completed`) para sincronizar status, planos e IDs no Supabase.
*   **Frontend**:
    *   Criada a página de gestão de assinatura (`assinatura.vue`) com UI para escolha de planos.
    *   Layout `workspace.vue` atualizado: inclui novo item no menu lateral e um **banner de bloqueio** que aparece automaticamente se o status da assinatura for `canceled`, `past_due` ou `unpaid`.
*   **Segurança e Regras de Negócio**:
    *   O endpoint de convite de usuários (`invite.post.ts`) agora valida:
        1. Se a assinatura está ativa (bloqueia convites se inativa).
        2. Se o workspace atingiu o limite de 3 agentes (bloqueia novos convites no plano "Starter").

### 2. Dependências e Configurações
*   **Pacote**: `stripe` (Node SDK) instalado.
*   **Variáveis de Ambiente (Adicionadas ao `.env`)**:
    *   `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET`, `STRIPE_PRICE_STARTER`, `STRIPE_PRICE_PRO`.
    *   Configuradas também no `nuxt.config.ts` via `runtimeConfig`.

### 3. Decisões de Design
*   Optamos por usar a abordagem de `Checkout Session` por ser a forma mais segura e recomendada pelo Stripe para processar assinaturas (PCI Compliance).
*   A sincronização é feita de forma assíncrona via webhooks, garantindo que o banco de dados do Supabase reflita o estado real do Stripe, mesmo que ocorram falhas temporárias na rede.
